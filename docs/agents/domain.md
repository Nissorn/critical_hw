# Domain docs

This repository uses a single-context domain layout.

## Before exploring

Read `CONTEXT.md` at the repository root if it exists.

Read ADRs under `docs/adr/` that touch the area being changed if that directory exists.

If either is absent, proceed without creating it pre-emptively. Create domain documentation only when a domain decision is actually resolved.

## Glossary

Use the vocabulary defined by `CONTEXT.md` when it exists. If a required term is not defined, use the smallest clear term and consider recording it through domain modeling.

## ADR conflicts

If a proposed change conflicts with an existing ADR, state the conflict explicitly and do not silently override it.
